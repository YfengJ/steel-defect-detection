# v0.1.2 Maintenance Design

## Goal

Finish the highest-value open-source maintenance work without changing the
vendored Ultralytics core or the project's training and inference contracts.

## Scope

The release completes three existing issues:

- Give GUI users actionable feedback before launching work with missing model,
  dataset, image, folder, or video paths.
- Document a first inference workflow that uses only user-provided local files.
- Record a real Apple Silicon MPS environment check and conservative fallback
  guidance.

It also adds missing repository governance files, runs the existing tests in CI,
and refreshes release and roadmap documentation for v0.1.2.

## Architecture

Path validation lives in a small root-level `path_validation.py` module. It has
no GUI, OpenCV, Torch, or Ultralytics imports, so tests can exercise it quickly.
`ui.py` calls these validators before spawning subprocesses or loading a video
model. Existing CLI entrypoints and the vendored `ultralytics/` package remain
unchanged except for small style or documentation corrections discovered by
the focused checks.

## Validation Contracts

- Model inputs must resolve to an existing file.
- Dataset configuration must be an existing YAML file with valid YAML content.
- Dataset `train` and `val` image entries must resolve to existing paths.
- YOLO label directories corresponding to `images/train` and `images/val` must
  exist.
- Image and video file sources must exist; numeric video sources remain valid
  camera identifiers.
- Batch prediction sources must be existing directories.
- Validation failures return concise Chinese messages with a concrete next
  action and a linkable documentation path where appropriate.

## Documentation And Governance

- Add `docs/sample_inference.md` with CPU-first commands plus optional MPS and
  CUDA notes. It must not introduce tracked samples, weights, or run outputs.
- Update `docs/macos.md` with the dated local MPS probe, environment details,
  fallback behavior, and a command users can repeat.
- Replace the inherited upstream contribution guide with repository-specific
  contribution and compatibility expectations.
- Add a Contributor Covenant code of conduct and a pull request template.
- Update README files, roadmap, and release notes to v0.1.2.

## CI And Repository Settings

CI keeps Python 3.10 as the compatibility baseline, installs runtime and
development test dependencies, runs repository hygiene checks, focused pytest
tests, CLI smoke tests, and compileall. The workflow receives read-only contents
permission, cancellation for superseded runs, and a time limit.

Repository topics and dependency vulnerability alerts are enabled through the
GitHub API. Heavy ML dependency upgrades remain excluded from automatic
Dependabot PRs until CPU, MPS, and CUDA compatibility can be reviewed.

## Error Handling

Validators return `None` for valid input and a user-facing string for invalid
input. The GUI displays that string in a message box and logs it without
starting background work. YAML parsing errors are summarized rather than
showing a raw traceback. Unexpected runtime exceptions continue through the
existing logging paths.

## Testing

- Unit tests cover valid and missing model, source, dataset image, and label
  paths, malformed YAML, and numeric camera sources.
- CLI smoke tests keep verifying all four command-line help entrypoints.
- Repository hygiene checks prevent tracked weights, datasets, generated runs,
  oversized files, CR line endings, and invalid GitHub YAML.
- A fresh Apple Silicon virtual environment verifies dependency installation,
  Torch MPS availability, and local CLI imports.
- Final validation reruns all focused tests, compileall, dependency consistency,
  diff checks, and the GitHub Actions workflow after push.

## Out Of Scope

- Refactoring the 43 KB GUI or vendored Ultralytics source tree.
- Shipping datasets, trained weights, generated outputs, or a network-downloaded
  sample asset.
- Automatically upgrading PyTorch, TorchVision, OpenCV, NumPy, SciPy, or the
  vendored Ultralytics snapshot.
- Claiming production inspection readiness or guaranteed MPS operator coverage.
